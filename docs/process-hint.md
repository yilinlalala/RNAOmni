> 配套落地步骤：[`relax-model-feature-constraints.md`](relax-model-feature-constraints.md)  
> 目的：依赖 **搜索过程**（这一轮动了哪一层、keep/discard 了什么）给出下一枪提示。不是因果识别。  
> **2026-08-22：** 思路定了，落地步骤见 [`process-hint-plan.md`](process-hint-plan.md)。本文不写实现细节。配套自由度已落地。换头在 C0 仍可均匀随机；`π(h|X)` 另开。

## 现在缺什么

开局是 `baseline`（现行 `train.py` / `Predictor`，**不是**菜单名，也 **不是**一次 `do(H)`）。  
换哪套 **named** 头 **不看任务、不看上一套表现**。平台期到了，编排器从剩余菜单均匀随机抽一个 `do(H=h)`，agent 必须实现这个名字。

这比让模型按感觉选头干净（干预和偏好是分开的），但抽完不用来更新下一步，也 **不问「Y 升不上去卡在哪一层」**。

升不上去时现行规则是机械的：连续 10 次 `[model]` discard 就换头，样本轴够数就扩 K，全局 patience 到了就停。`[feature]` / 样本 keep 之后旧头重新进池（只留当前 active）。

## 过程分层（够用即可）

```
任务/数据 X ──┬──→ 特征 F ──→ Y
              ├──→ 样本量 S ──→ Y
              ├──→ 训练旋钮 θ ──→ Y
              └──→ 头 H ──→ Y
```

平台期是观察：`Y 不动 | 已经做了若干次小改`。  
短板可能在不同层，对症下药必须是不同的 `do(·)`，不能一律换头。

两个量不要混：

| 估什么 | 对应动作 | 含义 |
|--------|----------|------|
| 骨架直接效应 | `framework_base` 第一枪 | 换积木本身有没有用 |
| 头 + 内环价值 | 该头后面若干次拧参 | 这套头占预算值不值得 |

提示「下一套试谁」应主要看第一行。历史 TSV 的 raw best 不能当排序：旧战役几乎只拧 `pool_mlp`，那是过程关联不是 `do(H)`。新战役开局 `baseline`、菜单 12 个头，仍不要用 raw best 排下一套。

`cause=` 是 **过程层标记**（这次动的是 H / F / θ / S / crash），不是因果估计。

---

## 要体现的思路

不是更聪明的 `π(下一套头 | 任务)`，而是：

**`π(动哪一层 | 过程证据)`**

每轮：看过程停在哪一层 → 只动该层 → 用结果修订笔记。

| 过程提示 | 动作 |
|----------|------|
| 骨架错 | `do(H)`：编排器从菜单抽下一套 named 头（开局 `baseline` 不算） |
| 特征不够 | `do(F)`：已登记开关 / tunable / 子集融合 |
| 拧参错 | `do(θ)`：框架内明旋钮 |
| 数据少 | `do(S)`：编排器扩 K |
| 实现坏了 | 修 crash（短签名） |

一次 discard 只说明「这个改动没抬 Y」，不能写成生物学结论。要看 **同一层上连续干预是否都无效**。说「是骨架」但换头后仍不动，就把 `head` 压下去，下一轮不准只换头。

换头仍由编排器 `do(H)`。Agent 可报 `cause=head`，不得自创类名。Prompt 里的说明只引导内环，不改选另一个名字。

## 和落地文档的关系

`relax-model-feature-constraints.md` 是在给上表每层补 **合法动作**（已登记菜单、旋钮、子集融合），不是打开自由发明，也不是提前换头。

过程提示侧最小落盘只需：

1. 瓶颈卡（短、固定字段）
2. 每轮 `cause=` → `do`
3. 把 `framework_base` 当成一次干预记录下来

对应落地 **C0**。有了这些再谈 `π(h | X)`。在此之前换头保持均匀随机，并留概率地板给没试过的头。

---

## 不要做

- 用旧战役分数或 LLM 常识当换头策略
- 用最终 val 当外环 RL 奖励（信用分不清）
- 为了提示去改 keep/discard、`min_delta`、评测合同
- 让 agent 读 `run.log` 或把 prompt 堆长
